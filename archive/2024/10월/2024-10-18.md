## AI 에이전트가 기업 데이터를 직접 조작하는 방식: Palantir CSE 구현 원리

**분야:** AI/에이전트 | **중요도:** 8점

**Palantir 발행일:** 2024-10-18T16:50:09.494000Z

**수집일:** 2026-10-29

*AI 에이전트가 기업 내부 데이터와 SOP를 어떻게 결합해 실제 업무 행동을 수행하는지 Palantir의 구현 사례를 통해 살펴본다.*

<mark>고객이 '주문 1005의 배송 예정일은 언제인가?'라고 묻는 순간, AI 에이전트는 단순히 텍스트를 분석하는 것을 넘어 SAP에서 주문 번호를 찾고, 머신러닝 모델을 호출해 배송 일자를 계산한 뒤 이메일 초안을 작성해야 한다.</mark> <mark>이러한 복잡한 업무 흐름을 AI가 자율적으로 처리하려면 기업 내부의 데이터 구조와 업무 규칙에 대한 깊은 이해가 필수적이다.</mark>

Palantir는 고객 서비스 엔진(CSE)의 두 번째 시리즈를 통해 AI 에이전트가 어떻게 기업 내 데이터 지형(Data Landscape)을 탐색하고, 표준 운영 절차(<strong>SOP</strong>)를 기반으로 실제 시스템 변경을 실행하는지 구체적으로 공개했다. 이 글은 AI가 '대화'를 '행동'으로 전환하기 위한 기술적 기반과 피드백 루프의 작동 방식을 설명한다.

![Palantir 대표 이미지](https://miro.medium.com/v2/resize:fit:1200/1*Tm85xrX2S5AfhnXQxqXEEw.jpeg)

### 데이터 지형과 에이전트 격리 구조

CSE의 에이전트는 SAP, Salesforce, 데이터 웨어하우스 등 소스 시스템에서 파이프라인을 통해 공급된 객체들(고객, 주문, 제품 등) 위에서 작동한다. 각 에이전트는 특정 목적을 위해 설계되며, 연결된 온톨로지의 특정 뷰에만 접근하도록 설정되어 데이터 접근 권한을 엄격히 관리한다.

예를 들어 배송 예정일 문의가 들어오면 분류 에이전트가 이를 식별하고, 주문 에이전트가 SAP에서 주문 번호를 확인한 뒤 머신러닝 기반 ETA 모델을 호출한다. 이렇게 생성된 결과는 마스터 에이전트로 전달되어 최종 응답 액션으로 변환된다.

### SOP 기반의 동적 액션 생성

에이전트가 실제 업무 변화를 일으키기 위해 'Actions' 온톨로지 원시 데이터를 사용한다. 이는 객체 편집, 외부 API 호출, 또는 <strong>Function on Objects</strong>를 통한 코드 실행을 포함한다. Palantir는 고객의 서비스 해결 프로세스를 분석해 액션 포트폴리오를 구축했으며, '배송일 변경' 액션은 온톨로지의 주문 객체와 ERP 기록을 동시에 업데이트하고 배송 파트너에게 알림을 보낸다.

정확한 액션을 선택하기 위해 고객의 표준 운영 절차(<strong>SOP</strong>)를 온톨로지에 의미론적으로 매핑해 저장했다. 'Suggested Actions Agent'는 이 <strong>SOP</strong>를 검색해 고객 쿼리를 해결하기 위한 액션 시퀀스를 동적으로 생성하며, 이는 응답 에이전트의 구조화된 프로세스를 가이드한다.

### K-LLM과 인간 피드백 루프

높은 정밀도가 필요한 작업에서는 단일 모델 대신 여러 LLM을 활용하는 K-LLM 방식을 적용한다. 이메일 생성과 같은 고객 소통 작업에서는 세 가지 다른 LLM의 출력을 비교해 가장 자연스러운 결과를 선택함으로써 환각 가능성을 크게 줄인다. 이 방식은 모델 편향을 완화하고, 모델 변경 시 유연성을 제공한다.

운영자가 에이전트의 제안 사항을 수정하거나 승인할 때 생성된 피드백은 온톨로지에 '피드백 객체'로 저장된다. 이 객체에는 예측의 계보와 오류 원인이 상세히 기록되며, 특정 제품 카테고리나 고객 세그먼트에 대한 요약 피드백은 에이전트가 유사한 쿼리를 처리할 때 컨텍스트로 주입되어 시스템의 자기 교정 능력을 강화한다.

### 정리하면

Palantir는 AI 에이전트가 기업 데이터를 읽고 실제 시스템 변경을 실행하는 구체적인 메커니즘과, 피드백을 통해 지속적으로 개선되는 학습 루프를 검증했다. 그러나 이 시스템이 프로덕션 환경에서 안정적으로 운영되기 위해서는 여전히 엄격한 모니터링, 평가 기준, 및 AI 모델 모니터링 체계가 필요하며, 이는 다음 단계에서 다뤄질 예정이다.
