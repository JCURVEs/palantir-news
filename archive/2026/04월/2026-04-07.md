## 브라우저에서 위성 궤도를 실시간으로: Palantir의 3D 지오스페이스 렌더링 전략

**분야:** 엔지니어링 | **중요도:** 8점

**Palantir 발행일:** 2026-04-07T13:58:01Z

**수집일:** 2026-10-29

*브라우저 기반 3D 렌더링으로 국방 데이터의 시각적 한계를 어떻게 돌파했는지 살펴본다.*

<mark>수만 개의 위성이 지구 주위를 돌고, 수천 개의 비행 경로가 실시간으로 업데이트되는 장면을 브라우저에서 부드럽게 보여주는 것은 단순한 그래픽 문제가 아니다.</mark> <mark>특히 국방 및 정보 작전에서는 네트워크가 불안정하고 오류가 허용되지 않는 환경에서 데이터의 흐름을 직관적으로 파악해야 한다.</mark>

Palantir 프론트엔드 엔지니어링 팀은 이러한 문제를 해결하기 위해 자체 개발한 3D 렌더링 라이브러리 'Zodiac'를 통해 Gotham 플랫폼의 Gaia 맵을 3D로 전환하는 과정을 공개했다. 이 글은 단순한 시각적 효과를 넘어, 브라우저의 성능 한계 내에서 방대한 지오스페이스 데이터를 처리하기 위한 구체적인 기술적 접근법을 보여준다.

![Palantir 대표 이미지](https://miro.medium.com/1*D_5LhinYPvt9spEjX8t_AA.png)

### 2D 맵의 한계를 넘어선 3D 좌표계 도입

기존의 Mercator 투영 방식은 고도 정보나 극지방의 왜곡을 정확히 표현하지 못해 우주 공간이나 고공 비행체 추적에 적합하지 않았다. Palantir는 이를 해결하기 위해 <strong>Three.js</strong>를 기반으로 한 Zodiac 라이브러리를 구축하여, Foundry Ontology의 지오스페이스 속성을 가진 객체를 3D 공간에 직접 렌더링하도록 했다.

이 구조에서는 백엔드가 데이터 저장과 필터링, 무거운 계산을 담당하고 프론트엔드는 단순한 기하학과 스타일 정보만 받아 렌더링에 집중한다. 이를 통해 사용자는 실제 세계와 동일한 공간 개념으로 데이터를 이해할 수 있으며, 위성 충돌 위험이나 <strong>궤도</strong> 예측 등 복잡한 시나리오를 시각적으로 확인할 수 있다.

### GPU 인스턴싱으로 해결한 고밀도 렌더링 병목

수만 개의 위성을 동시에 표시할 때 브라우저의 그래픽 성능은 극한에 달한다. Palantir는 동일한 기하학을 가진 수천 개의 위성을 하나의 드로우 콜(draw call)로 처리하는 인스턴스드 메시(Instanced Mesh) 기술을 적용했다. 이를 통해 10,000개의 선이 동일한 스타일을 가질 경우 하나의 GPU 연산으로 처리되어 성능 저하를 방지했다.

위성 위치 계산에는 1960년대부터 사용된 TLE(Two-Line Elements) 형식을 활용했으며, 클라이언트는 기본적인 <strong>궤도</strong> 전파만 수행하고 충돌 분석이나 장기 예측 같은 무거운 계산은 Foundry 컴퓨트 모듈에서 서버 측으로 처리하도록 분리했다. 이러한 분업은 브라우저의 제한된 리소스 내에서 실시간성을 유지하는 핵심 전략이었다.

### 슬라이딩 윈도우로 궤도 계산량 95% 절감

위성 <strong>궤도</strong> 경로를 시각화할 때 초기 방식은 선택된 위성의 약 2일 치 <strong>궤도</strong>를 매 프레임마다 처음부터 다시 계산하는 것이었다. 이는 하드웨어 사양이 낮은 환경이나 다중 객체 선택 시 시스템이 무너질 정도로 비효율적이었다.

Palantir는 시간 함수의 특성을 이용해 '<strong>슬라이딩 윈도우</strong>' 방식을 도입했다. 이미 계산된 <strong>궤도</strong> 데이터를 큐 형태로 관리하고, 시간이 지나면 앞부분의 데이터를 버리고 뒷부분에 새로운 데이터만 추가하는 방식이다. 이를 통해 선택된 객체당 계산량을 95%까지 줄여 더 많은 <strong>궤도</strong> 경로를 동시에 렌더링할 수 있게 되었다.

### 시간 필터링과 셰이더를 활용한 효율적 가시성 제어

실시간 데이터에서 특정 시간대에만 표시해야 하는 라인(예: 비행 경로)을 처리할 때, 매 프레임마다 배열을 재할당하는 것은 메모리 낭비를 초래한다. Palantir는 지오메트리를 한 번만 생성하고, 시간 변화에 따라 가시성만 제어하는 방식을 채택했다.

각 라인에 시간 필터 함수를 연결하고, 가시성이 실제로 변경될 때만 GPU 버퍼의 투명도(opacity) 값을 업데이트한다. 셰이더를 통해 투명도가 0에 가까우면 픽셀을 렌더링하지 않도록 하여, 불필요한 그래픽 처리를 최소화하면서도 부드러운 시각적 전환을 구현했다.

### 정리하면

Palantir의 이 접근법은 브라우저라는 제한된 환경에서도 국방급 데이터의 복잡성을 시각적으로 풀어내는 기술적 성취를 보여준다. 특히 계산량 절감과 GPU 효율화 전략은 대규모 지오스페이스 데이터 처리의 새로운 기준을 제시한다. 다만, 이 기술이 실제 현장 작전에서의 의사결정 속도나 정확도에 미친 정량적 영향은 아직 공개되지 않았으며, 향후 더 다양한 데이터 소스와의 통합 과정에서 성능 한계가 어떻게 극복될지 주목된다.
