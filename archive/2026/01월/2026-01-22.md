## 에이전트 보안의 5가지 축: Palantir AIP의 프로덕션 배포 전략

**분야:** 보안/거버넌스 | **중요도:** 9점

**Palantir 발행일:** 2026-01-22T15:22:27.459000Z

**수집일:** 2026-10-29

*AI 에이전트가 실제 업무에 투입될 때, 데이터와 로직을 어떻게 통제해야 하는지 Palantir의 기술적 해결책을 살펴본다.*

<mark>AI 에이전트가 기업 내부의 민감한 데이터에 접근하고 외부 시스템에 명령을 내리는 순간, 기존의 단순한 역할 기반 보안 정책으로는 위험을 막기 어렵다.</mark> <mark>특히 유럽 데이터에 접근할 권한이 없는 사용자에게 관련 결과가 노출되거나, 승인되지 않은 외부 API로 데이터가 유출되는 사고는 치명적이다.</mark>

Palantir는 AIP의 Agentic Runtime을 통해 이러한 문제를 해결하기 위해 보안 아키텍처를 5가지 핵심 차원으로 나누어 설계했다. 이번 글은 프로토타입을 넘어 프로덕션으로 넘어가는 과정에서 에이전트의 추론, 메모리, 도구 사용, 그리고 활동 기록이 어떻게 통제되는지 그 메커니즘을 구체적으로 분석한다.

![Palantir 대표 이미지](https://miro.medium.com/v2/resize:fit:1200/1*iZhGzaE5cBQEDvV-n7yuQA.png)

### 48시간 수명 제한으로 보장되는 인프라 격리

Palantir는 에이전트 실행을 위한 기반 인프라로 <strong>Rubix</strong>라는 강화된 Kubernetes 환경을 사용한다. 이 환경에서는 모든 워크로드가 필요한 요구사항에 따라 안전하게 격리되며, 워크로드 간 모든 상호작용은 인증, 인가, 로그 기록이 필수적이다.

<strong>Rubix</strong>의 핵심 특징은 노드의 수명을 48시간으로 제한하는 것이다. 이러한 일시적(ephemeral) 인프라 설계는 에이전트가 프로코드(Code Workspaces)나 로우코드(AIP Logic) 환경에서 실행되더라도, 노드 장애 시에도 서비스가 중단되지 않고 자동으로 대체 노드로 전환되는 회복력을 제공한다.

### Ontology를 통한 4가지 기억 형태의 통합 통제

에이전트의 기억은 작업, 에피소드, 의미, 절차 기억으로 나뉘며, Palantir는 이 모든 것을 <strong>Ontology</strong> 시스템으로 통합 관리한다. 물류 지원 에이전트 사례에서 볼 수 있듯, 초기화 시 절차 기억과 시스템 프롬프트가 <strong>Ontology</strong> 객체에서 로드되고, 실행 중에는 벡터 유사도 검색을 통해 과거의 학습(에피소드 기억)이 제어 루프에 반영된다.

이 과정에서 보안 정책은 런타임마다 동적으로 계산된다. 예를 들어 PII를 포함한 사용자 데이터에 대한 접근은 보안 마킹으로 제한되며, 특정 속성을 가진 인간 사용자의 대리인으로만 작동할 때 고객 상세 정보를 조회할 수 있도록 조건부가 설정된다. 이는 인간과 에이전트 모두에게 동일한 보안 표면을 적용하여 공격 벡터를 최소화한다.

### 데이터 출처를 추적하는 프로베넌스 기반 도구 보안

에이전트가 데이터를 조회하거나 ERP 상태를 변경하는 등 도구를 사용할 때, 시스템 레벨의 강제 적용이 이루어진다. 특히 DevCon 4에서 소개된 프로베넌스 기반 보안은 데이터 소스에 부여된 제어가 더 복잡한 도구로 중첩될 때도 런타임에 전체 호출 체인을 추적하여 준수되도록 한다.

컴파일 타임에는 정책 위반 시 새로운 도구 버전의 배포를 차단하고 개발자에게 명확한 오류 메시지를 제공한다. 또한 외부 시스템과의 연결 시에는 Palantir 정보 보안 팀이 관리하는 인프라 방화벽 외에도, 개발자가 설정한 이그레스 정책이 모든 아웃바운드 연결을 통제하여 승인되지 않은 데이터 유출을 방지한다.

### 데이터에서 결정까지 추적 가능한 실시간 관측

비결정론적인 에이전트의 신뢰성은 관측 가능성에 달려 있다. AIP는 분산 트레이스를 통해 개별 LLM 쿼리, 함수 호출, 변환 과정을 시각화하며, 각 데이터 쿼리는 해당 데이터 소스의 전체 버전 히스토리와 변환 로직과 연결된다.

LLM 기반 함수의 경우, 관련 Evals 스위트가 자동으로 추적되어 정성적 또는 정량적 기준 내에서 호출과 응답이 어떻게 변화했는지 세밀하게 회계 처리된다. 이러한 텔레메트리 로그의 접근 권한도 데이터 마킹과 동일한 보안 원리에 의해 통제되며, 실시간 스트리밍 데이터셋이나 외부 시스템으로의 수출이 명시적으로 설정되어야 한다.

### 정리하면

Palantir의 이 접근법은 에이전트 보안이 개별 기능의 합이 아니라, 인프라 격리부터 데이터 거버넌스까지 통합된 시스템으로 작동해야 함을 보여준다. 다만, 이 글은 보안 아키텍처의 설계 원리를 중심으로 다루며, 실제 운영 환경에서의 성능 지표나 구체적인 실패 사례 분석은 후속 글에서 다룰 예정이다.
