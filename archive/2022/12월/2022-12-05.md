## 데이터 보안과 투명성의 딜레마를 푸는 Palantir의 운영 보안 전략

**분야:** 보안/거버넌스 | **중요도:** 8점

**Palantir 발행일:** 2022-12-05T18:04:04Z

**수집일:** 2026-10-29

*보안 강화가 협업의 적이 아닌 친구가 되는 데이터 거버넌스 설계 원칙을 살펴본다.*

<mark>많은 기업은 데이터 보안 강화를 위해 접근 권한을 엄격히 제한하는 것을 당연시한다.</mark> <mark>이는 데이터 소유자로 하여금 오용을 두려워해 데이터를 사일로화하게 만들고, 결과적으로 조직 전체의 생산성과 투명성을 떨어뜨리는 원인이 된다.</mark>

Palantir는 이러한 '보안 대 투명성'의 위장된 딜레마를 해결하기 위해, 보안 정책이 데이터와 함께 이동하고 목적에 따라 접근이 정밀하게 제어되는 운영 보안 역량을 RFx(입찰 제안서) 평가 기준으로 제시했다.

### 경직된 RBAC의 한계와 목적 기반 접근 제어의 도입

전통적인 역할 기반 접근 제어(RBAC)는 권한을 팀이나 그룹 단위로 묶어 관리하기 때문에, 데이터 소유자는 잘못된 사용자에게 데이터가 노출될까 두려워 접근을 과도하게 제한하는 경향이 있다. Palantir는 이를 해결하기 위해 '<strong>목적 기반 접근 제어(PBAC)</strong>'를 제안한다.

PBAC에서는 사용자가 특정 데이터셋에 대한 무제한 접근을 요청하는 대신, 구체적인 업무 목적에 기반하여 접근을 신청한다. 데이터 거버넌스 팀은 이 목적에 맞는 데이터만 승인함으로써, 사용자가 목표 달성에 필요한 최소한의 데이터만 접근하도록 보장한다.

### 데이터 전파를 통제하는 보안 마킹과 Discoverer 권한

보안 마킹은 데이터에 분류 라벨을 부여하여, 해당 라벨이 데이터가 변환되거나 파생되는 모든 하위 자산으로 전파되도록 강제하는 메커니즘이다. 이는 원본 데이터의 보안 수준이 파생된 보고서나 분석 결과물까지 유지되도록 하여, 보안 정책이 데이터의 생명주기 전반에 걸쳐 일관되게 적용되도록 한다.

또한 Palantir는 'Discoverer' 권한을 도입하여, 사용자가 데이터의 실제 내용을 보지 않고도 리소스의 이름과 메타데이터만 확인할 수 있게 한다. 이는 데이터 자산의 존재 자체를 완전히 숨기거나, 반대로 불필요하게 노출시키는 것 사이의 균형을 잡아주어, 필요한 사용자에게만 접근 요청의 기회를 제공한다.

### 비기술 사용자를 위한 암호화 및 선택적 공개 워크플로우

민감한 개인정보 처리 시, Palantir는 비기술 사용자도 데이터를 암호화, 복호화, 해싱할 수 있는 기능을 제공한다. 이는 보험 관리자가 특정 멤버의 사회보장번호를 보기 위해 정당한 사유를 제시해야 하는 '<strong>선택적 공개 워크플로우</strong>'를 가능하게 한다.

모든 암호화 작업은 감사 가능하도록 설계되어, 누가 어떤 데이터를 언제 복호화했는지 추적할 수 있다. 이를 통해 데이터 보호 책임자는 중앙에서 누가 어떤 범주의 데이터에 접근할 수 있는지 정확히 관리하고 감사할 수 있다.

### 정리하면

Palantir의 제안은 보안이 데이터 생태계의 성장을 방해하는 장벽이 아니라, 신뢰를 바탕으로 한 협업을 가능하게 하는 인프라가 될 수 있음을 보여준다. 그러나 이러한 기능들이 실제 조직 환경에서 얼마나 효율적으로 운영되는지는 해당 조직의 데이터 거버넌스 성숙도와 시스템 통합 수준에 따라 달라질 수 있다.
