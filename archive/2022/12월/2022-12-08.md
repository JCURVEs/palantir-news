## API 설계의 함정: '강력함'보다 '사용자 결과'를 우선하는 Palantir의 선택

**분야:** 엔지니어링 | **중요도:** 6점

**Palantir 발행일:** 2022-12-08T18:22:46.226000Z

**수집일:** 2026-10-29

*Kubernetes 스케줄링 사례를 통해, 과도한 일반화가 가져오는 기술적 부채와 사용자 중심 API 설계의 실질적 이점을 살펴본다.*

<mark>Kubernetes 클러스터에서 Spark 애플리케이션을 실행할 때, 여러 가용 영역(AZ)에 흩어져 있는 포드들은 네트워크를 통해 대량의 데이터를 주고받아야 한다.</mark> <mark>이 과정에서 발생하는 데이터 전송 비용과 지연을 줄이기 위해, 모든 포드를 하나의 AZ 안에만 배치하는 스케줄링 로직이 필요해졌다.</mark>

Palantir 프로덕션 인프라 팀은 이 문제를 해결하는 과정에서 '더 강력하고 일반적인 API'를 만드는 것이 항상 좋은 결과로 이어지지 않음을 깨달았다. 이번 발표는 특정 스케줄링 요구사항을 충족하기 위해 어떤 API를 선택했는지, 그리고 왜 더 유연해 보이는 옵션을 포기했는지를 구체적으로 설명한다.

![Palantir 대표 이미지](https://miro.medium.com/v2/resize:fit:1200/1*SBCxa642AVVjSaRU40KOdw.png)

### 단일 AZ 스케줄링의 필요성과 기존 구조의 한계

Spark 애플리케이션의 포드들은 서로 대량의 데이터를 전송하므로, 이를 단일 가용 영역(AZ)에 모아두면 상당한 데이터 전송 비용을 절감할 수 있다. Palantir는 기존에 FIFO 방식으로 포드를 배치하고 건강한 AZ에만 노드를 할당하는 기반을 갖추고 있었지만, 특정 애플리케이션 전체를 단일 AZ로 제한하는 기능은 없었다.

기존 스케줄러는 모든 AZ의 노드를 고려하여 빈 패킹을 수행했다. 단일 AZ 스케줄링을 위해 스케줄러가 각 AZ별 노드를 나열하고 해당 로직을 호출하는 방식은 이미 충분한 여유 용량이 있는 경우에만 작동한다. 만약 특정 AZ에 충분한 자원이 없다면, 오토스케일링 컴포넌트가 해당 자원을 확보해야 하는데, 이때 '단일 구역'이라는 제약 조건을 어떻게 전달할지가 핵심 문제가 되었다.

### Zone 필드 vs. 불리언 플래그: API 설계의 갈림길

Palantir는 두 가지 API 확장 옵션을 검토했다. 첫 번째는 Demand 스펙에 'Zone' 문자열 필드를 추가해 스케줄러가 원하는 구역을 직접 지정하는 방식이다. 두 번째는 '<strong>EnforceSingleZoneScheduling</strong>' 불리언 필드를 추가해 단일 구역 스케줄링을 요청하는 방식이다.

'Zone' 필드를 사용하면 스케줄러가 각 AZ의 건강 상태와 확장성 정보를 직접 파악해야 한다. 이 정보는 원래 오토스케일링 컴포넌트 내부에서만 관리되던 것이므로, 이를 외부로 노출하면 스케줄러가 오토스케일링 로직을 중복 구현하거나 잘못 구현할 위험이 생긴다. 이는 생산 환경에서 지속적인 스케줄링 실패로 이어질 수 있는 심각한 의존성 문제를 초래한다.

### 사용자 결과에 초점을 맞춘 최종 결정

결국 Palantir는 '<strong>EnforceSingleZoneScheduling</strong>' 불리언 필드를 선택했다. 이 방식은 스케줄러가 특정 구역을 고르는 부담을 덜어주면서도, 오토스케일링 컴포넌트가 내부적으로 최적의 구역을 선택할 수 있는 유연성을 유지한다.

이 결정은 사용자의 실제 목표인 '단일 구역 내 컴퓨트 확보'에 정확히 맞춰져 있다. 과도한 일반화를 피함으로써 사용자의 인지 부하를 줄이고, 동시에 인프라 팀의 미래 개발 자유도를 보호하는 균형점을 찾은 것이다.

### 정리하면

이 사례는 API의 '강력함'이 곧 사용자 성공을 의미하지는 않는다는 점을 명확히 보여준다. Palantir는 작은 설계 결정 하나하나가 시스템의 지속가능성에 영향을 미친다고 강조하며, 사용자 결과를 정밀하게 추출하는 과정을 중요시한다. 다만, 이 접근법이 모든 복잡한 분산 시스템에 보편적으로 적용되는지 여부는 구체적인 컨텍스트에 따라 달라질 수 있다.
