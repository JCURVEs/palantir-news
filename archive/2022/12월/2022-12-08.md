## [Palantir] Palantir 프로덕션 인프라: 사용자 결과 중심의 API 설계 원칙

**분야:** 엔지니어링 | **중요도:** 6점

**원문발행일:** 2022-12-08T18:22:46.226000Z

**수집일:** 2026-10-09

**요약:**  
Palantir 프로덕션 인프라 팀은 엔지니어링 노력이 사용자의 실제 결과(outcome)를 달성하는 데 집중되어야 한다고 강조합니다. 일반적인 '강력한' API를 만들려는 경향이 사용자에게 불필요한 복잡성을 부과하거나 내부 추상화를 누출시킬 수 있음을 지적합니다. Spark 애플리케이션 스케줄링 개선 사례를 통해, 사용자의 구체적 목표를 정확히 파악하여 최소한의 표현력으로 문제를 해결하는 API 설계가 장기적으로 더 효과적임을 보여줍니다. 이 접근법은 사용자 경험과 개발자의 향후 유지보수 유연성을 동시에 보장합니다.

**쉬운설명:**  
사용자가 원하는 결과를 가장 단순하고 명확하게 도와주는 도구를 만드는 것이 중요하다는 내용입니다. 기능이 많고 복잡한 도구보다는, 사용자가 쉽게 사용할 수 있도록 딱 필요한 부분만 제공하는 것이 장기적으로 더 좋습니다.
