## 데이터 사이언티스트의 '반응형' 역할, '능동형'으로 전환하는 Foundry Ontology

**분야:** 데이터 플랫폼 | **중요도:** 8점

**Palantir 발행일:** 2022-12-19T22:03:54.646000Z

**수집일:** 2026-10-29

*모델 배포 이후의 피드백 루프를 통해 데이터 사이언티스트가 실제 비즈니스 결정에 직접 개입하는 방식을 살펴봅니다.*

<mark>데이터 사이언티스트는 모델이 배포된 후 실제 업무 현장에서 어떻게 사용되고 있는지, 그리고 어떤 결과를 낳았는지 알기 어렵습니다.</mark> <mark>대부분의 시간은 데이터 탐색과 승인 절차에 소모되며, 모델의 실제 효과 평가에는 자원이 부족합니다.</mark>

Palantir는 <strong>Foundry Ontology</strong>가 이러한 단방향 구조를 어떻게 양방향 피드백 루프로 전환하는지 설명합니다. 이 글은 데이터 사이언티스트가 조직의 프로세스를 직접 파악하고, 모델을 신속하게 배포하며, 운영 현장의 반응을 실시간으로 반영하는 메커니즘을 다룹니다.

![Palantir 대표 이미지](https://miro.medium.com/v2/resize:fit:1200/1*UMcKKAb8q2cI9VOLPpDKVw.png)

### 조직 프로세스 지도화를 통한 병목 식별

기존에는 데이터 사이언티스트가 경영진으로부터 추상적인 지시를 받은 후, 각 부서의 전문가(SME)에게 의존하여 필요한 배경 지식을 수집해야 했습니다. 이 과정은 분절된 지식 전달로 인해 비효율적이었습니다.

Ontology는 조직의 엔티티와 관계를 하나의 지도로 제공하여 데이터 사이언티스트가 직접 시스템 간 연결고리를 파악할 수 있게 합니다. 이를 통해 누구와 상담하고 어떤 모델을 만들어야 하는지 스스로 결정할 수 있어, 전문가 의존도를 낮추고 솔루션 최적화에 집중할 수 있습니다.

### 데이터 확보 시간 단축과 모델 배포 간소화

데이터 자산이 데이터 레이크나 웨어하우스에 분산되어 있어, 관련 데이터를 찾는 데 수개월이 걸리는 경우가 많았습니다. Ontology는 실제 비즈니스 프로세스와 'Actions'를 데이터 객체에 연결하여, 이를 데이터 사이언스 타깃으로 표출합니다.

이 방식은 데이터 레이크를 깊이 있게 탐색하거나 복잡한 승인 체인을 거칠 필요 없이 관련 데이터를 신속하게 확보할 수 있게 합니다. 또한 ML 엔지니어가 모델을 컨테이너화하고 엔드포인트를 설정하는 별도 단계를 생략하여, 데이터 사이언티스트가 모델 훈련부터 배포까지를 직접 수행할 수 있는 민첩한 사이클을 만듭니다.

### 운영 현장 피드백을 모델 개선에 즉시 반영

모델이 배포된 후에도 사용자가 추천을 무시하는 경우, 그 이유를 파악하기 어려웠습니다. Ontology의 <strong>writeback</strong> API를 통해 데이터 사이언티스트는 하위 애플리케이션에 유용성 토글과 댓글 상자를 추가하여 즉각적인 피드백을 수집할 수 있습니다.

예를 들어, 사용자가 추천의 근거를 이해하지 못해 신뢰하지 않는다는 피드백이 들어오면, 데이터 사이언티스트는 모델의 <strong>feature importances</strong>를 예측 결과와 함께 노출하는 투명성 조치를 몇 시간 내에 배포할 수 있습니다. 이러한 실시간 피드백 루프는 모델의 신뢰도를 높이고 비즈니스 영향력을 정량화하는 데 기여합니다.

### 정리하면

Palantir는 Ontology가 데이터 사이언티스트의 역할을 수동적 분석가에서 능동적 문제 해결자로 전환한다고 강조합니다. 다만 이 글은 구체적인 정량적 성과 수치보다는 프로세스 개선의 메커니즘과 사례를 중심으로 설명하고 있어, 실제 도입 시 기대되는 효율성 향상 정도는 개별 조직의 환경에 따라 달라질 수 있습니다.
