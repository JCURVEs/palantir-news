## Palantir, 전사 FIDO2 강제 적용을 위한 YubiKey 물류 및 선택 전략

**분야:** 보안/거버넌스 | **중요도:** 8점

**Palantir 발행일:** 2022-11-18T16:55:24Z

**수집일:** 2026-10-29

*Palantir가 전사 비밀번호 폐기를 위해 하드웨어 인증기 물류와 데이터 기반 운영을 어떻게 설계했는지 살펴본다.*

<mark>고급 피싱 공격과 자격 증명 탈취가 일상화된 환경에서, Palantir는 10년 이상 유지해온 다중 인증(MFA)의 한계를 극복하기 위해 하드웨어 기반 FIDO2 인증으로 전환을 결정했다.</mark> <mark>수천 명의 전 세계 직원이 다양한 운영체제와 고객사 현장에서 일하는 상황에서, 모든 사용자가 물리적으로 장치를 소유하고 인증해야 하는 새로운 체계를 구축하는 것은 기술적 도전 이상이었다.</mark>

이 글은 Palantir 정보보안 팀이 YubiKey를 선택하고 배포하기까지의 과정, 특히 자체 주문 포털 구축과 <strong>Palantir Foundry</strong>를 활용한 데이터 기반 롤아웃 전략을 상세히 설명한다. 하드웨어 인증 도입의 핵심이 기술 스택이 아닌 물류와 사용자 경험 관리에 있음을 보여주는 사례를 통해, 조직이 어떻게 '가정된 침입(Assume Breach)' 원칙을 실제 인프라에 적용하는지 확인한다.

![Palantir 대표 이미지](https://miro.medium.com/1*s7gyKlEdgkUBjHdornXE3g.png)

### 플랫폼 인증기 대신 로밍 인증기를 선택한 이유

Palantir는 초기 배포에서 노트북이나 스마트폰에 내장된 플랫폼 인증기 대신, USB 형태로 연결하는 <strong>로밍 인증기</strong>를 선택했다. 이는 일부 디바이스가 기업용 내부 인증기 통합을 지원하지 않아 프로젝트 일정을 지연시킬 수 있었기 때문이며, 내부 인증기는 키를 다른 장치로 내보내거나 동기화할 수 있어 가용성과 보안 간의 트레이드오프 문제가 있었다.

또한 상당수의 사용자가 고객사 현장에서 다른 장치를 사용해야 하는 상황에서, <strong>로밍 인증기</strong>는 이러한 제한적인 환경에서도 유연하게 작업할 수 있게 해준다. 단일 외부 인증 플랫폼을 사용하는 것은 물류 관리와 사용자 교육을 단순화하고, 모든 플랫폼에서 일관된 경험을 제공하는 데 기여했다.

![Palantir 이미지 2](https://miro.medium.com/v2/resize:fit:1200/1*WWrHmkBBxqOMuKo1DiZ0oA.png)

### YubiKey 5 FIPS 선정과 공급망 보안 고려사항

Palantir는 공급망 보안, <strong>FIPS 140-2</strong> 검증된 암호화, 네이티브 FIDO2 지원, 그리고 전 세계 인력을 위한 물류 요구사항을 충족하는 <strong>YubiKey 5 FIPS</strong> 시리즈를 최종 선택했다. 이 키는 미국에서 제조되어 공급망 공격에 대한 우려를 줄이고, 강력한 인증 기능을 제공하며, 선택적인 코드 서명 사용 사례를 지원한다.

특히 YubiKey의 정전용량(capacitance) 기능은 사용자가 키를 물리적으로 터치해야만 인증이 완료되도록 하여, 사용자가 해당 장치에 물리적으로 존재한다는 요구사항을 충족시킨다. 이는 원격 피싱이나 사회적 공학 공격을 물리적으로 차단하는 핵심 메커니즘으로 작용한다.

### 자체 주문 포털과 YubiEnterprise API 활용

전 세계에 분산된 수천 명의 직원을 위해 Palantir는 YubiEnterprise 프로그램에 가입하여 API 기반 주문 및 글로벌 배송을 활성화했다. 자체 구축한 포털을 통해 사용자는 중앙 운영팀과 소통하지 않고도 직접 키를 주문할 수 있으며, 키는 사용자가 실제로 일하는 장소(사무실, 고객사, 원격지, 가정)로 배송된다.

이 포털은 Yubico가 직접 물류를 처리하도록 하여 Palantir의 운영 부담을 줄였으며, 사용자는 자신의 워크플로우에 맞는 폼 팩터와 백업 키를 선택할 수 있었다. 결과적으로 배포된 YubiKey의 대부분은 이 자동화된 경로를 통해 인간 개입 없이 처리되었다.

### Palantir Foundry를 활용한 데이터 기반 롤아웃 관리

Azure AD에 일급의 비밀번호 없는 강제 적용 메커니즘이 부재했던 시점에서, Palantir는 자체 분석 플랫폼인 Foundry를 지휘 및 통제 시스템으로 활용했다. Azure AD에서 수집된 원시 인증 데이터를 다른 인증 시스템과 상관 분석하여, 미등록 사용자나 플랫폼 특정 문제를 가진 사용자를 식별하는 대시보드를 구축했다.

Foundry를 기반으로 한 자동화 워크플로우는 사용자가 비-FIDO2 방식으로 인증을 시도했을 때 실시간으로 봇 알림을 보내고, 매일 엔드포인트 통지를 통해 워크플로우를 재조정하도록 유도했다. 이러한 정밀한 데이터 분석과 사전 개입 덕분에 최종 강제 적용 시점에 예상보다 적은 사용자 잠금 사례와 기술 지원 부하가 발생했다.

### 정리하면

Palantir의 사례는 FIDO2 도입이 단순한 기술 스택 교체가 아니라, 물류, 데이터 분석, 사용자 행동 변화가 결합된 복합적인 보안 엔지니어링 과제임을 보여준다. 약 16개월에 걸친 이 프로젝트는 하드웨어 인증의 보안 이점이 크지만, 성숙하지 않은 플랫폼 기능과 엣지 케이스 처리에 상당한 비용과 노력이 수반됨을 입증한다. 다음 단계에서는 강제 적용 구현, 롤아웃 전략, 그리고 구체적인 엣지 케이스 처리에 대한 상세 정보가 제공될 예정이다.
