## 브라우저 확장 프로그램, '차단' 대신 '코드'로 통제하는 Palantir의 보안 전략

**분야:** 보안/거버넌스 | **중요도:** 8점

**Palantir 발행일:** 2022-11-23T14:01:58Z

**수집일:** 2026-10-29

*브라우저 확장 프로그램의 보안 리스크를 코드 기반 워크플로우로 관리하는 Palantir InfoSec 팀의 실무 사례를 살펴본다.*

<mark>웹 브라우저는 기업 내 민감한 업무의 주요 인터페이스이지만, 사용자가 자유롭게 설치하는 브라우저 확장 프로그램은 키로깅이나 데이터 탈취 등 심각한 보안 위협이 될 수 있다.</mark> <mark>특히 개인 계정과 업무 계정이 동기화되거나, 웹스토어에서 삭제된 악성 확장 프로그램이 여전히 활성화된 상태로 남아있는 경우가 흔하다.</mark>

Palantir 정보보안팀은 이러한 문제를 해결하기 위해 확장 프로그램 관리를 '코드'로 정의하는 방식을 도입했다. 이 글은 Palantir가 어떻게 <strong>osquery</strong> 데이터를 활용해 허용 목록을 구성하고, GitHub와 CI/CD 파이프라인을 통해 Windows와 macOS 환경에 정책을 배포하는지 그 구체적인 작동 방식을 보여준다.

![Palantir 대표 이미지](https://miro.medium.com/1*YN1upw3mzIdGBLn6Ewx0Fw.png)

### osquery 데이터로 실제 사용 패턴 파악 및 허용 목록 구성

Palantir는 기존에 알려진 악성 확장 프로그램만 차단하는 denylist 방식의 한계를 인식하고, 전체 엔터프라이즈 환경에 설치된 확장 프로그램을 조사하기 시작했다. 이를 위해 <strong>osquery</strong> 데이터셋을 조회하여 Chrome, Edge, Firefox 세 브라우저와 Windows, macOS 두 운영체제에서 설치된 확장 프로그램의 설치 빈도를 순위별로 분석했다.

조사 결과, 수백 개의 고유 확장 프로그램이 단 1~2대의 워크스테이션에만 설치되어 있거나, 웹스토어에서 이미 삭제되었음에도 여전히 활성화된 상태인 경우가 발견되었다. 또한 개인 Google 계정으로 Chrome에 로그인해 개인용과 업무용 확장 프로그램이 동기화되어 악성 코드가 업무 네트워크로 전파될 위험이 있었다. 이러한 데이터를 바탕으로 Palantir는 설치 횟수, 광고된 기능, 기업 환경에서의 유용성을 기준으로 초기 허용 목록을 선별했다.

### GitHub 기반 코드 정의와 CircleCI 자동 검증 파이프라인

허용 목록은 내부 GitHub 저장소의 JSON 파일로 관리되며, 각 브라우저별로 별도의 파일을 유지한다. 직원들은 새로운 확장 프로그램이 필요할 때 직접 Pull Request를 열거나 티켓을 제출하여 요청할 수 있으며, 이 과정에서 보안 팀은 제안된 확장 프로그램의 권한과 프라이버시 정책을 검토할 시간을 확보한다.

PR이 생성되면 <strong>CircleCI</strong> 자동화 시스템이 JSON 문법 오류, 확장 ID 중복 여부, 그리고 해당 확장 프로그램이 실제 웹스토어에 존재하는지 여부를 검증한다. 특히 Chrome 웹스토어의 경우 HTTP 요청을 보내 확장 ID의 유효성을 확인하고, 웹스토어에 등록된 이름과 JSON 파일에 명시된 이름이 일치하는지 대조하여 오입력이나 사기성 항목을 탐지한다. 이 검증 과정은 PR이 열리지 않은 날에도 매일 정기적으로 실행되어, 승인된 확장 프로그램이 웹스토어에서 삭제되었는지 모니터링한다.

### Windows 자동 배포와 macOS 반자동 관리의 차이

Windows 환경에서는 검증된 확장 ID 목록을 레지스트리 경로에 적용하는 PowerShell 스크립트를 통해 그룹 정책(GPO)을 자동으로 업데이트한다. 이 스크립트는 기존 설정을 삭제하고 새로운 JSON 기반 정책을 레지스트리에 기록하여, 도메인 관리자가 수동으로 확장 ID를 입력할 필요가 없도록 한다.

반면 macOS 환경에서는 <strong>Jamf Pro</strong> API를 통한 완전 자동화가 생산 환경에서 안전하게 실행되지 않아 제한적이었다. Palantir는 내부 서비스인 <strong>Excavator</strong>를 활용하여 GitHub의 JSON 파일을 파싱하고, <strong>Jamf Pro</strong> 관리자가 쉽게 적용할 수 있는 <strong>plist</strong> 파일을 자동으로 생성하는 반자동 방식을 채택했다. 이 방식은 관리자가 변경 사항을 하나씩 찾아볼 필요 없이 업데이트된 <strong>plist</strong> 파일 전체를 한 번에 업로드할 수 있게 하여 업무 부담을 줄였지만, 여전히 수동 적용 단계가 남아 있다.

### 정리하면

Palantir의 이 접근법은 브라우저 확장 프로그램이라는 복잡한 보안 문제를 코드 기반의 워크플로우로 전환하여, 보안 팀의 수동 관리 부담을 줄이고 직원들의 업무 유연성을 보장하는 균형을 맞췄다. 다만 macOS 환경의 완전 자동화가 아직 해결되지 않은 과제로 남아 있으며, 이 코드 저장소 기반 워크플로우는 다른 조직에 그대로 적용하기보다는 각 조직의 인프라와 정책 체계에 맞게 수정해야 하는 점을 유의해야 한다.
