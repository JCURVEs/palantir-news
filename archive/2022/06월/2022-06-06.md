## Palantir, 일회성 원격 워크스페이스로 개발 속도 78% 향상

**분야:** 엔지니어링 | **중요도:** 7점

**Palantir 발행일:** 2022-06-06T14:14:27Z

**수집일:** 2026-10-29

*일회성 인프라와 원격 개발의 결합이 개발 생산성에 미치는 실질적 영향과 비용 구조를 분석한다.*

<mark>수백 명의 개발자가 동시에 작업하는 대형 소프트웨어 프로젝트에서, 로컬 노트북의 성능 한계는 개발자의 집중력을 끊고 빌드 시간을 길게 만드는 주요 원인이 된다.</mark> <mark>특히 머신러닝 훈련이나 대규모 테스트가 필요한 환경에서는 개인용 기기로는 감당하기 어려운 컴퓨팅 자원이 요구된다.</mark>

Palantir DevOps 팀은 이러한 문제를 해결하기 위해 '일회성(ephemeral) 인프라'와 '원격 워크스페이스'를 결합한 새로운 개발 환경을 구축했다. 이 글은 해당 시스템이 어떻게 작동하며, 실제 개발 주기와 비용에 어떤 변화를 가져왔는지를 구체적인 수치와 함께 살펴본다.

![Palantir 대표 이미지](https://miro.medium.com/1*HwrY5EneuuIscebY5g--Cg.png)

### 엔터프라이즈 환경의 표준화 및 성능 문제 해결

대규모 조직에서는 개발 환경의 표준화가 필수적이지만, 로컬 머신마다 다른 설정으로 인해 '내 컴퓨터에서는 잘 된다'는 문제가 빈번하게 발생한다. 또한 ML 훈련이나 대규모 테스트에 필요한 GPU나 RAM 등 고사양 자원은 개인용 노트북으로 충족하기 어렵다.

Palantir는 이러한 문제를 해결하기 위해 개발자가 직접 VM을 관리하는 대신, Kubernetes 기반의 표준화된 원격 환경을 제공했다. 이를 통해 개발 환경이 프로덕션 환경과 유사하게 유지되고, 인프라 팀의 패치 및 업데이트 부담도 줄였다.

### Coder와 EKS 기반 일회성 워크스페이스 구현

Palantir는 <strong>Amazon EKS</strong> 위에서 <strong>Coder</strong>를 활용해 개발자가 클릭 몇 번으로 필요한 리소스를 프로비저닝하고 종료할 수 있는 시스템을 구축했다. <strong>Coder</strong>는 GitHub Enterprise와 네이티브로 통합되어 SSH 키 관리와 리포지토리 클로닝을 자동화하며, 개발자는 자신의 dotfiles와 스크립트를 커스터마이징할 수 있다.

이 시스템은 '일회성'이라는 개념을 적용해 사용하지 않는 시간에는 인스턴스를 자동으로 종료한다. 이를 통해 개발자는 필요할 때 즉시 고사양 환경을 사용할 수 있고, 인프라 팀은 개별 개발자의 환경 설정을 일일이 관리할 필요가 없어졌다.

### 빌드 시간 78% 단축과 비용 구조 분석

실제 테스트에서 4.5GB 크기의 <strong>mono-repo</strong> 기반 Foundry 프론트엔드 빌드 시간은 78% 단축되었고, 코드 저장소와 아티팩트 서버가 물리적으로 가까운 위치에 있어 git clone 시간도 71% 줄었다. 이러한 속도 향상은 개발자가 '플로우' 상태에 진입하는 시간을 줄여 전체 조직의 생산성을 높이는 데 기여했다.

비용 측면에서는 32GB M1 MacBook(연간 약 $1,500) 대신 표준 M1 MacBook(연간 약 $1,000)과 <strong>r5.4xlarge</strong> EC2 인스턴스(연간 약 $8,830)를 사용하는 구조로 전환했다. 3명의 개발자가 하나의 인스턴스를 공유하고, 주말 및 비업무 시간에는 인스턴스를 종료하는 최적화를 통해 총 비용은 약 41% 증가했으나, 이는 생산성 향상으로 정당화되었다.

### 정리하면

Palantir의 사례는 원격 개발 환경이 단순한 편의 기능이 아니라, 대규모 엔터프라이즈 개발의 병목을 해결하는 핵심 인프라임을 보여준다. 다만, 이 모델의 효과는 프론트엔드 저장소에서 가장 뚜렷하게 나타나며, Java 프로젝트 등 다른 기술 스택에서의 IDE 호환성과 사용자 경험은 아직 테스트 단계에 있다. 향후 더 넓은 범위로의 확장은 이러한 검증 과정의 결과에 달려 있다.
