## Palantir, Apollo로 IL6 보안 요구사항을 어떻게 충족했나

**분야:** 보안/거버넌스 | **중요도:** 8점

**Palantir 발행일:** 2023-02-28T15:54:42.441000Z

**수집일:** 2026-10-29

*격리된 국방 네트워크에서 소프트웨어를 안전하게 배포하고 유지보수하는 Palantir Apollo의 구체적 작동 방식을 살펴본다.*

<mark>인터넷에 연결되지 않은 격리된 환경에서 보안 취약점이 발견되면, 패치를 적용하기까지 수 시간이 걸리거나 수동으로 복잡한 승인 절차를 거쳐야 한다.</mark> <mark>이러한 지연은 국방 및 정보 기관의 핵심 시스템에 치명적인 리스크를 초래할 수 있다.</mark>

Palantir는 2022년 10월 미국 국방정보시스템국(DISA)으로부터 IL6 임시 인가를 획득하며, Apollo 플랫폼이 이러한 고도 보안 환경의 요구사항을 어떻게 충족하는지 상세히 공개했다. 이번 발표는 단순한 인증 획득을 넘어, Apollo가 NIST 위험 관리 프레임워크(RMF)의 주요 제어 항목들을 어떻게 자동화하고 구현하는지 기술적 메커니즘에 초점을 맞춘다.

![Palantir 대표 이미지](https://miro.medium.com/v2/resize:fit:1200/1*1jujUexmm1P_9i5Ih51Vqw.png)

### 자동 취약점 스캔으로 공급망 리스크 관리

현대 애플리케이션은 수백 개의 오픈소스 라이브러리로 구성되며, 매일 새로운 취약점이 발견된다. Apollo는 이러한 공급망 리스크를 관리하기 위해 컨테이너 취약점 스캔 기능을 내장하고 있다.

새로운 릴리스가 생성되면 Apollo는 자동으로 MITRE의 CVE 목록과 대조하여 알려진 취약점을 검색한다. 취약점이 발견되면 해당 제품을 개발하는 팀에 즉시 알람을 보내 패치를 유도하며, 정보 보안 팀은 취약점 심각도를 기준으로 IL6 요구사항 내에서 배포 가능한 범위를 정의한다.

### 중앙 승인 프로세스를 통한 구성 변경 통제

Apollo는 각 마이크로서비스에 대해 YML 기반의 구성 파일을 관리하며, 모든 변경 사항은 변경 요청(CR)으로 생성된다. IL6 환경에서는 이러한 CR이 중앙 운영 팀인 <strong>Baseline</strong>으로 전송되어 승인 과정을 거친다.

<strong>Baseline</strong> 팀은 변경 사항이 서비스 장애를 일으키지 않는지 검증한 후, 지정된 유지보수 윈도우 내에서만 적용을 승인한다. 이 과정은 변경 이력을 감사 로그로 남겨두며, 프로덕션 환경에 미검증된 오류가 도입되는 것을 방지한다.

### 격리 환경에서의 빠른 패치 배포 및 복구

보안 사고 발생 시 Apollo는 네트워크 경계를 넘어 코드 업데이트를 빠르게 전달할 수 있다. 제품 소유자가 코드 수정을 완료하면 Apollo는 IL6 보안 프로토콜에 따라 NOC 팀이 전파하는 대로 자동으로 업그레이드를 수행한다.

Apollo는 인프라와 설정을 분리한 템플릿을 사용하여 '소(소)가 아닌 가축(가축)' 접근법을 적용한다. 이는 비밀 정보와 설정이 Kubernetes 클러스터나 VM에서 분리되어 있어, 사고 시 특정 노드를 격리하고 새 인프라에 설정을 재적용하는 과정을 단순화한다.

### 모니터링과 최소 권한 원칙 기반 접근 제어

Apollo는 <strong>Prometheus</strong> 메트릭 형식을 지원하는 플랫폼 내 모니터링 기능을 제공하여, 서비스 이상을 실시간으로 감지한다. 알림은 NOC 팀의 인박스로 라우팅되며, 관련 서비스 로그와 Apollo 활동이 자동으로 연결되어 신속한 대응을 돕는다.

접근 제어 측면에서 Apollo는 모든 API와 액션에 역할을 매핑한다. 환경 운영 권한은 <strong>Baseline</strong> 팀에, 제품 수명 주기 관리 권한은 개발 팀에 부여하는 등 최소 권한 원칙을 적용하여 보안성을 강화한다.

### 정리하면

Palantir는 Apollo를 통해 평균 3.5분 만에 서비스를 패치하고 프로덕션 문제 해결 시간을 5분 이내로 줄이는 구체적인 성과를 입증했다. 이는 격리된 환경에서도 소프트웨어 공급망과 운영 보안을 자동화할 수 있음을 보여준다. 다만, 이러한 효율성은 Apollo 플랫폼의 특정 기능과 Palantir 내부의 <strong>Baseline</strong> 운영 프로세스가 결합되었을 때 달성된 결과이며, 다른 조직이 동일한 효과를 얻기 위해서는 유사한 수준의 프로세스 표준화가 필요하다.
