## 데이터 삭제부터 시작하는 프라이버시: Palantir Foundry의 전 주기 보호 원칙

**분야:** 보안/거버넌스 | **중요도:** 8점

**Palantir 발행일:** 2023-06-16T16:46:48.552000Z

**수집일:** 2026-10-29

*데이터가 플랫폼에 들어와서 사라질 때까지, Palantir가 프라이버시를 기술적으로 구현하는 방식을 살펴본다.*

<mark>병원, 국방부, 유럽 마케팅 부서 등 가장 민감한 데이터를 다루는 기관들은 Palantir 플랫폼을 신뢰하기 전에 까다로운 보안 요구사항을 통과해야 한다.</mark> <mark>단순히 데이터를 저장하는 것을 넘어, 데이터가 어떻게 생성되고, 변형되며, 최종적으로 사라지는지 전 과정을 통제해야 하기 때문이다.</mark>

Palantir는 20년간 축적된 엔지니어링 경험을 바탕으로, 데이터 라이프사이클의 각 단계에 프라이버시 원칙을 내재화한 Foundry 플랫폼의 작동 방식을 공개했다. 이 글은 데이터가 유입되는 순간부터 삭제될 때까지, 어떤 기술적 장치가 개입하여 프라이버시를 보호하는지 구체적으로 설명한다.

![Palantir 대표 이미지](https://miro.medium.com/v2/resize:fit:1200/1*Ba_yX_HKUjrAcsf1rxHJeQ.png)

### 데이터 유입 전 거버넌스 매핑과 접근 통제

데이터가 Foundry에 들어오기 전, 데이터 카탈로그를 통해 보안 및 거버넌스 요구사항을 정의한다. 이렇게 기록된 거버넌스 지시사항은 데이터와 함께 플랫폼 내에 위치하여, 데이터 컨텍스트를 파악하고 사용하는 과정을 단순화한다.

사용자가 민감한 데이터를 데이터 연결이나 드래그 앤 드롭으로 가져올 때, <strong>Checkpoints</strong>가 개입하여 사전에 설정된 프롬프트를 표시하거나 정당성을 요구한다. 이를 통해 잠재적으로 민감한 행동을 취하기 전에 거버넌스 통제가 작동하며, 관리자 권한과 마킹(markings), 제한된 뷰를 통해 사용자별 접근 권한을 세분화하여 관리한다.

### PII 감지 및 데이터 최소화 전략

데이터가 플랫폼에 착륙하면 Foundry Inference가 조직별 민감 데이터 정의를 기반으로 PII를 감지한다. PII가 탐지되면 플랫폼은 즉시 해당 데이터셋을 잠금 처리하거나 리뷰어에게 경고를 보내, 승인된 공간에만 존재하고 적절한 사용자만 접근할 수 있도록 한다.

데이터 준비 단계에서는 재식별 가능성을 줄이기 위해 다양한 최소화 전략을 적용한다. PII를 코드나 포인트 앤 클릭으로 제거하거나, 개별 데이터를 집계하여 식별력을 낮추고, 연령 범주화 같은 일반화를 통해 세부 정보를 억제한다. 또한 <strong>Foundry Cipher</strong>를 사용해 민감한 값을 기본적으로 암호화하고, 정당한 사유가 있는 승인된 사용자만 해독을 요청할 수 있게 한다.

### 데이터 계보를 통한 감사 및 삭제 프로토콜

데이터가 사용자와 상호작용하는 동안, <strong>Data Lineage</strong> 도구를 통해 누가 어떤 데이터에 접근했는지 추적한다. 데이터 내보내기나 다운로드 시 <strong>Checkpoints</strong>를 활용해 목적 기반 접근 제어를 적용하고, 모든 상호작용은 플랫폼 내에서 감사 로그로 기록되어 이상 행위나 무단 접근 패턴을 모니터링하는 데 사용된다.

데이터의 수명이 끝나면, 데이터 계보를 활용해 법적 보유 기간이나 잊힐 권리(Right to be Forgotten)에 따라 삭제를 수행한다. Foundry는 접근 제어, 애플리케이션, 저장소, 백업, 클라우드 인프라 순서로 각 계층의 리소스를 체계적으로 삭제하는 프로토콜을 제공하여 데이터가 완전히 제거되었음을 보장한다.

### 정리하면

Palantir의 이 접근법은 규제 준수를 위한 단순한 체크리스트가 아니라, 프라이버시 원칙을 기술 아키텍처의 첫 단계부터 반영한 결과물이다. 이는 기술 발전 속도에 뒤처지지 않는 미래 지향적인 보안 체계를 구축하는 데 기여하지만, 구체적인 성능 지표나 실측 성과 수치보다는 원칙적 프레임워크와 도구 구성에 초점을 맞추고 있다.
