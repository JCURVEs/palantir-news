## 9일 만에 구축한 난민 정착 플랫폼, 12만 명 이상을 어떻게 연결했나

**분야:** 국방/공공 | **중요도:** 8점

**Palantir 발행일:** 2023-08-08T20:21:20Z

**수집일:** 2026-10-29

*대규모 난민 수용 과정에서 데이터 분산과 보안 문제를 어떻게 해결했는지 Palantir의 운영 사례를 살펴본다.*

<mark>2022년 3월 영국 정부의 'Homes for Ukraine' 프로그램이 시작되자, 단 24시간 만에 12만 건 이상의 민간 주택 제공 의사가 쏟아졌다.</mark> <mark>그러나 수만 건의 비자 신청과 수십만 건의 숙박 제안이 서로 다른 정부 시스템에 흩어져 있어, 지방 정부는 누가 언제 도착하는지 알 수 없었고 중앙 정부는 숙소 적합성을 판단하기 어려웠다.</mark>

Palantir는 이 복잡한 데이터 정체를 어떻게 풀어냈을까? 이 글은 Palantir가 9일 만에 구축한 Foundry 기반 플랫폼이 <strong>온톨로지</strong>(Ontology)를 통해 데이터를 통합하고, 보안과 협업을 동시에 달성하여 12만 명 이상의 난민 정착을 지원한 과정을 상세히 분석한다.

![Palantir 대표 이미지](https://miro.medium.com/1*xnLfVB8KNb14VwJZg-iMSQ.png)

### 분산된 데이터 통합과 온톨로지 구축

기존 시스템에서는 오프라인 스프레드시트에 흩어져 있던 데이터를 연결할 수 없어 현장 상황 파악이 불가능했다. Palantir는 Foundry의 온톨리지를 활용해 데이터, 운영, 분석을 하나의 상호 운용 가능한 플랫폼으로 결합했다.

이 과정에서 중복된 비자 신청을 식별하고 여행 그룹을 파악하는 등 데이터 품질 문제를 해결했으며, 복잡한 기술적 세부사항을 '게스트', '호스트', '숙박'과 같은 직관적인 용어로 변환하여 사용자의 인지 부하를 줄였다.

### 보안과 협업을 동시에 만족하는 접근 제어

민감한 난민 데이터를 다뤄야 하는 만큼, 데이터 보안과 협업 사이의 트레이드오프를 피하는 것이 핵심 과제였다. Palantir는 '<strong>목적 기반 접근 제어</strong>'를 적용하여 승인된 사용자만 특정 목적과 기간 동안만 데이터에 접근할 수 있도록 제한했다.

모든 데이터 접근에 대해 끝-to-끝 감사 추적을 제공함으로써, 이전에는 불가능했던 수준의 보안 하에서 중앙 및 지방 정부 간의 실시간 협업을 가능하게 했다.

### 실시간 의사결정 지원과 효율성 향상

3,000명 이상의 사례 담당자가 동일한 최신 데이터 뷰를 공유함으로써, 한 사용자가 우려 사항을 플래그하면 하위 단계의 의사결정자에게 즉시 알림이 전달되는 워크플로우가 구축되었다.

데이터 품질 개선이 중앙에서 이루어짐으로써 지방 정부 기관들이 개별적으로 데이터를 정리하는 데 드는 노력을 절감하고, 난민 지원에 더 많은 자원을 투입할 수 있게 되었다.

### 정리하면

이 사례는 데이터 플랫폼이 단순한 기술 도구가 아니라, 대규모 인도적 위기 상황에서 행정적 마찰을 줄이고 신속한 대응을 가능하게 하는 핵심 인프라임을 보여준다. 다만, 이 시스템의 지속 가능성과 향후 다른 위기 상황으로의 확장 가능성은 아직 검증되지 않은 영역으로 남아 있다.
