## [Palantir] Git 병합 속도 9000배 향상: Palantir 엔지니어의 최적화 시리즈 최종 결과

**분야:** 엔지니어링 | **중요도:** 8점

**원문발행일:** 2021-09-20T21:08:20Z

**수집일:** 2026-10-23

**요약:**  
기존 Git 병합 알고리즘인 merge-recursive는 인덱스 배열의 삽입 및 삭제 시 O(N^2) 시간 복잡도를 유발하고, 리네임 감지를 위해 트리를 반복적으로 탐색하는 비효율적인 구조를 가지고 있었다. Palantir 엔지니어 Elijah Newren은 이러한 문제를 해결하기 위해 merge-ort를 개발하여 인메모리 인덱스 수정을 피하고 병합 결과를 트리로 생성한 후 체크아웃하는 방식을 도입했다. 또한 부분 클론 환경에서 필요한 객체를 일괄적으로 사전 가져오는(prefetching) 로직을 개선하여 네트워크 요청 횟수를 대폭 줄였다. 이 최적화들은 'mega-renames' 테스트 케이스(26,000개 리네임 포함 35개 커밋 리베이스)에서 실행 시간을 5,964초에서 661.8밀리초로 단축시켰다. 이는 이론적으로 리네임 감지만 무한정 병렬화했을 때의 예상 시간(203.8초)보다도 훨씬 빠른 결과로, 리네임 감지 외의 병목 현상까지 제거했음을 보여준다. 이러한 개선으로 인해 Microsoft는 파일 수가 Linux 커널의 25배 이상인 대형 모노레포에서 리네임 감지 기능을 다시 활성화하는 방안을 검토하기 시작했다. 현재 대부분의 최적화는 Git 2.34 버전부터 적용되며, 일부 'Preview only' 기능은 여전히 개발 중이다.

**쉬운설명:**  
수만 개의 파일이 이름이 바뀌는 복잡한 코드 통합 작업을 기존 방식으로는 약 1.6시간이 걸렸지만, Palantir 엔지니어가 개발한 새로운 알고리즘을 적용하면 0.6초 만에 끝낼 수 있게 되었습니다. 이는 마치 방대한 도서관에서 필요한 책만 미리 골라 한꺼번에 가져오는 방식으로, 불필요한 검색과 이동 시간을 크게 줄인 것과 같습니다.
