## [Palantir] Git 병합 성능 최적화: 불필요한 이름 변경 탐지 제거와 'ort' 전략 도입

**분야:** 엔지니어링 | **중요도:** 8점

**Palantir 발행일:** 2021-03-08T13:51:22.861000Z

**수집일:** 2026-10-29

**요약:**  
Palantir 엔지니어는 리눅스 커널 규모 모노레포에서 대규모 리팩토링 시 Git의 기존 병합 알고리즘이 재베이스 및 체리픽 과정에서 수개월에 걸친 지연을 유발하는 문제를 해결하기 위해 새로운 병합 전략 'ort'를 개발했다. 기존 알고리즘은 파일 내용 비교를 통한 이름 변경 탐지 시, 이미 해시 값이 동일한 완벽한 매칭을 찾았음에도 더 나은 매칭을 찾기 위해 불필요한 대조 작업을 반복하는 비효율적인 구조를 가지고 있었다. 이를 개선해 해시가 일치하는 파일 쌍은 즉시 이름 변경으로 확정하고, 복사 탐지가 아닌 순수 이름 변경 탐지 시에만 불필요한 비교를 생략하도록 로직을 수정했다. 이 최적화는 약 26,000개 파일이 이름이 변경된 브랜치에 35개 패치를 재베이스하는 테스트에서 처리 시간을 5,504초에서 1,799초로 약 3배 단축시키는 실측 성과를 보였다. 또한 단일 커밋 체리픽 테스트에서도 2배의 속도 향상이 확인되었으며, 이 변경 사항은 git-2.31 릴리스에 포함될 예정이다. 향후 작업으로는 인덱스 기반 희소성(sparse index) 지원과 같은 더 근본적인 데이터 구조 재설계가 계획되어 있다.

**쉬운설명:**  
수만 개의 파일이 이름만 바뀌고 내용은 그대로인 경우, 기존 Git은 내용을 다시 열어보며 확인하는 불필요한 작업을 반복했지만, 이제는 파일의 고유 식별자(해시)가 같으면 바로 이름 변경으로 인정하고 넘어가도록 하여 병합 속도를 크게 높였다.

## [Palantir] Git 병합 성능 최적화: 파일명 기반 리네임 감지 알고리즘 도입

**분야:** 엔지니어링 | **중요도:** 6점

**Palantir 발행일:** 2021-03-08T13:51:31.331000Z

**수집일:** 2026-10-29

**요약:**  
Palantir 엔지니어는 Git의 병합 과정에서 발생하는 리네임(파일 이름 변경) 감지의 비효율성을 해결하기 위해 파일의 기본 이름(basename)을 활용한 최적화 알고리즘을 제안했습니다. 실제 리포지토리 분석 결과, 파일 이동 시 기본 이름이 유지되는 경우가 대부분임을 확인하여 이를 통해 불필요한 전수 비교를 줄였습니다. 이 최적화로 인해 대규모 리네임이 포함된 Linux 커널 테스트 케이스의 병합 시간이 약 30분에서 2분으로 단축되었습니다. 해당 기본 최적화는 git-2.31에, 추가적인 디렉터리 예측 로직은 git-2.32에 반영될 예정입니다.

**쉬운설명:**  
Git이 파일 이름이 바뀌었는지 판단할 때 모든 파일 내용을 하나씩 비교하는 대신, 파일 이름의 핵심 부분만 먼저 확인하는 지름길을 만들어 병합 속도를 크게 높였습니다.

**출처:** https://blog.palantir.com/optimizing-gits-merge-machinery-2-d81391b97878
