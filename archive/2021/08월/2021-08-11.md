## [Palantir] REST API 설계에서 CRUD 패턴의 한계와 대안

**분야:** 엔지니어링 | **중요도:** 7점

**원문발행일:** 2021-08-11T15:36:19Z

**수집일:** 2026-10-05

**요약:**  
Palantir 엔지니어는 초기 API 설계에서 흔히 사용되는 CRUD(생성, 읽기, 수정, 삭제) 패턴이 실제 운영 환경에서 비효율적일 수 있음을 지적합니다. 특히 동시성 문제, 부분 수정의 복잡성, 그리고 검색 및 보안 변경 처리의 부재가 주요 문제로 꼽힙니다. 이를 해결하기 위해 Get-and-Set, Get-and-Patch, 타임스탬프 기반 낙관적 동시성 제어, 그리고 부가 전용 로그(Append-Only-Log) 등 워크플로우에 맞춘 대안 패턴을 제안합니다. API 설계 시 클라이언트의 실제 사용 패턴과 동시 편집 처리 방식을 사전에 고려하는 것이 장기적인 서비스 안정성에 중요하다고 강조합니다.

**쉬운설명:**  
데이터를 저장하고 관리하는 표준 방식인 CRUD가 모든 상황에 적합하지 않다는 점을 설명하며, 문서 편집기나 은행 계좌처럼 특정 상황에서는 더 효율적인 다른 관리 방법들이 필요하다고 조언합니다.
